# AstraCode Architecture

**Status:** Target architecture, updated with implemented workspace foundation.

## System boundary
```text
Compose UI → ViewModel/use case → policy/service → repository → Android/provider adapter
```
UI renders state; repositories/adapters own I/O; policy owns validation and approvals.

## Package direction
Keep the one-module app until boundaries stabilize. Gradually introduce common, navigation, design system, security, local persistence, workspace and feature packages. Avoid mass moves.

## Contracts
1. Persisted SAF tree URI defines workspace scope. Never use arbitrary paths outside that grant.
2. Keep blocking document-provider operations off the main thread and map failures to actionable UI messages.
3. Cloud AI only; no bundled Android SDK.
4. Protected operations require capability checks, approval as appropriate, audit and verification.
5. Model output is not proof of completion; propagate cancellation and typed failures.
6. Protect credentials and keep them out of logs.
7. One preference source of truth.
8. Every user-facing change is documented in Help & Guide and `IMPLEMENTATION.md`.

## Cloud AI provider boundary

The provider-neutral contract is in `CloudAiProvider.kt`: requests, messages, model capabilities, token usage, typed outcomes and sanitized failure categories do not depend on a vendor SDK. `CloudAiRouter` resolves an explicit provider/model target and checks its advertised output limit before execution. Unknown providers/models and unsupported output limits are typed rejections; there is deliberately no automatic cross-provider fallback because that could disclose project content to a different vendor. Provider implementations own cloud HTTP details and credential lookup, must propagate coroutine cancellation, and must return sanitized failure detail. The provider boundary is connected to live adapters, encrypted credentials, model discovery and Chat. Provider/model selection is explicit, with no automatic cross-provider fallback.

`CloudAiProviderCatalog.kt` defines metadata for OpenRouter, OpenAI, custom OpenAI-compatible endpoints, Gemini, Anthropic, xAI, DeepSeek, Mistral AI, Groq, Together AI, Fireworks AI, Perplexity, Cerebras, SambaNova, NVIDIA NIM and Cohere. Each definition records its expected protocol, default HTTPS API root when known, official documentation URL, credential label and whether a custom base URL is supported. OpenAI Responses, OpenAI-compatible Chat Completions, Gemini generateContent, Anthropic Messages and Cohere Chat v2 are distinguished instead of treating every vendor as wire-compatible. `CloudAiAdapters.kt` implements HTTP request/response mappings for those five protocols through `CloudAiProviderFactory`. Credentials and transport are injected, allowing tests to validate serialization and parsing without live keys. The HTTPS transport disables redirects, uses bounded request/response sizes and timeouts, and maps HTTP statuses to sanitized typed failures without copying response bodies to user-visible errors. Model capability maps are explicit; until discovery/configuration provides a model capability, adapters reject it. `AiProviderSettings.kt` stores provider/model/endpoint preferences separately from API keys and encrypts each key with an AES-GCM key held by Android Keystore. Provider ID is authenticated as GCM additional data to prevent ciphertext from being silently reassigned between providers. Encrypted secret preferences are excluded from cloud backup and device transfer. `AiProviderSettingsScreen.kt` exposes provider, manual model ID, optional custom HTTPS base URL, masked key entry, save/remove actions and an explicit connection test using a short prompt; users are warned the request may incur provider charges and does not include workspace files. A successful test proves only that the configured model answered that request, not that streaming, vision or tool execution are ready. `CloudAiModelDiscovery.kt` implements authenticated GET-based model listing for the catalogued protocols: OpenAI-compatible and OpenAI `/models`, Gemini `models`, Anthropic `/v1/models` and Cohere `/v1/models`. Responses are validated and capped before reaching UI state; unsupported model-list schemas produce sanitized failures. `AiChatScreen.kt` now uses the saved provider/model and encrypted credential source to send conversations through the provider factory. It supports cancellation, typed error messaging, a 60-message history bound and a capped displayed response. Chat does not implicitly attach workspace data. Chat conversations are persisted locally by AiChatSessionStore using SQLite. The schema keeps sessions and messages separate, enables foreign-key cascades, bounds history to 25 sessions and 60 messages per session, clamps titles/messages, and excludes the chat database from Android backup to avoid copying potentially sensitive prompts. The Chat UI can create, restore and delete sessions; user messages are saved before the provider request and assistant answers are saved locally when returned. Chat supports explicitly selected any-MIME attachments through Android's document picker. Up to three files may be selected, with a 25 MiB cap per file and a 25 MiB aggregate attachment budget per provider request. The reader streams bytes into app-private storage instead of loading the full file during selection; SQLite schema v3 stores attachment metadata and display content, not raw bytes, and migrates existing sessions. Provider adapters encode supported text/image/document/audio/video inputs natively and return a typed error for unsupported provider/format combinations. The UI names the supported-modality limitation and warns that explicitly selected file contents are sent to the configured model and saved in local history; workspace files are never attached automatically. Workspace tool requests are handled by AiWorkspaceToolProtocol and AiWorkspaceToolExecutor. The parser accepts only an exact, bounded one-action envelope and an explicit allow-list: workspace_list, workspace_read and workspace_create_file. Relative paths reject absolute paths and traversal; creation additionally requires a recognized text/code name and valid UTF-8 content of at most 16 KiB. The executor resolves all paths from the persisted Android Storage Access Framework tree root. Listing returns at most 40 entries; reads require strict UTF-8 and are capped at 16 KiB. Creation is restricted to a new file beneath an existing workspace folder: it refuses existing paths, checks the storage provider's returned name, writes only after explicit approval, reads the file back and compares bytes exactly, then records the relative path, byte count and SHA-256 evidence. A durable approval audit containing action, path and reason is written before invoking the executor; creation audits also contain the proposed content hash, and an audit-write failure prevents execution. Declines and tool results are recorded in chat. Tool output is untrusted workspace data. Overwrite, move, delete, terminal, build and autonomous multi-step execution remain planned.

## Workspace/editor
Code uses Android's system tree picker, storing the SAF tree URI and persistent read permission. Directory queries and all mutations use `DocumentsContract` with document IDs in the selected tree. Create, rename, delete and move errors are surfaced if the provider doesn't support an operation. Moving a directory into itself or a descendant is blocked. Supported text/code files use a debounced autosave editor capped at 2 MiB; read-only provider documents and truncated files remain read-only. Case-insensitive plain-text find/replace operates on the in-memory draft. Dirty writable drafts are debounced to an app-private, no-backup local file using atomic writes; a baseline SHA-256 must match before a draft can be restored, and stale/corrupt drafts are discarded. Saving or explicitly discarding removes the recovery copy. Up to eight editor tabs can be switched without losing in-memory draft text or selection; an asterisk marks dirty tabs. Closing a dirty tab offers to persist a recoverable draft or discard it. Recovery copies remain app-private, while editable workspace drafts now auto-save to the SAF document after a 900 ms pause. Before each write AstraCode re-reads the stored file and compares it with the editor's last saved baseline; a detected external change pauses autosave rather than silently overwriting it. The user can compare stored content with the current draft, reload storage, or explicitly confirm an overwrite. This check reduces accidental conflicts but cannot provide an atomic compare-and-swap guarantee across arbitrary document providers. A single bounded diff engine/view is reused for workspace-vs-draft and local-snapshot-vs-draft comparisons. A read-only folding view computes UTF-8 byte count, line count and longest-line metrics only when opened, and scans supported brace-based languages while ignoring common strings and comments. Analysis is capped at 2 MiB and 1,500,000 lines; files outside those bounds show metrics but do not produce a line listing or fold regions. The view uses an IntArray line-offset index and lazy Compose rows instead of materializing each line and row. Fold-region storage is capped at 50,000 regions, and nesting tracking at 20,000 levels; reaching either safety limit preserves the line listing while stopping further fold detection. Lines longer than 4,000 characters are clipped in the inspection list. This is intentionally a separate inspection view: returning to Edit source restores the normal source buffer and avoids mapping edits through hidden text. Web Live Preview renders the current draft for HTML/HTM, CSS and JavaScript after a short debounce. The preview uses a restrictive CSP and WebView settings that disable network loads, file/content access, external navigation, DOM storage and multi-window creation. CSS and JavaScript are wrapped in a small sample page; HTML remains standalone. Sibling files and external resources are intentionally not loaded yet. Preview source is capped at 2 MiB and appears below the still-editable source field, updating after a 300 ms debounce; the preview itself never writes files, while edits to its source draft follow the normal debounced workspace-autosave and conflict-check policy. Local snapshots are app-private, capped at ten per file and 2 MiB each; a bounded LCS diff is used for small inputs and a compact summary is used when the matrix would be too large. Restoring a snapshot replaces only the current draft immediately; that draft then follows the normal autosave and conflict-check policy.

## UI
Chat, Code, Git, Build and More are the top-level destinations. A tested 600 dp width policy selects bottom navigation below the breakpoint and a navigation rail at/above it. Destination labels remain available to accessibility services; the custom navigation glyph is decorative where the visible label already names the destination. Primary selection, More search query and the selected More subsection use saveable state for activity recreation. The UI smoke suite verifies More search/selection restoration after recreation. More is searchable and includes Help & Guide. Incomplete sections remain labelled placeholders.

## Current state
The repo has the bootstrap shell, responsive navigation, searchable More/Help, SAF browser and CRUD, debounced autosave/conflict detection, local draft recovery, bounded editor tabs/snapshots, read-only code folding and sandboxed Web Live Preview. Cloud AI providers, encrypted credentials, model discovery, chat with durable local sessions, selected multimodal attachments, and approval-gated list/read/create-only workspace tools are implemented. Git/GitHub actions, builds, AI overwrite/move/delete tools and end-to-end task verification remain planned and tracked in `docs/ROADMAP.md`.


## Approval-gated AI workspace tools

Workspace tools use a strict, size-bounded envelope and an allow-list. The UI requires explicit approval for every proposal, writes an approval audit record to durable chat history before executing, and records results or decline decisions. If the pre-execution audit write fails, the executor is not called. workspace_list lists a bounded directory and workspace_read reads a small UTF-8 text/code file beneath the persisted SAF root. workspace_create_file adds one new recognized text/code file of at most 16 KiB beneath an existing directory. It rejects invalid paths/content, refuses an existing path, writes only after approval, checks the provider-preserved name, reads the resulting bytes back and compares them exactly before reporting success with path, byte count and SHA-256 evidence. If verification fails, cleanup is attempted and the result says when cleanup could not be confirmed. Overwrites, moves, deletes, shell, build and end-to-end task verification remain unimplemented.


## Multimodal Chat Attachments

The system picker accepts arbitrary file types. AiChatAttachmentReader copies a selected document through a bounded stream into app-private ai_chat_attachments storage. Raw bytes are never placed in SQLite: schema v3 stores only validated attachment IDs, filenames, MIME types and byte counts on the message record. Files and the chat database are excluded from cloud backup and device transfer. Each file is limited to 25 MiB; up to three files can be selected, and the raw attachment payload hydrated into one provider request is capped at 25 MiB. The JSON transport cap is 64 MiB to accommodate inline Base64 encoding. Provider adapters encode modalities in their native content shapes where supported: Gemini inline data for images/audio/video/documents, OpenAI Responses image/file parts, OpenAI-compatible Chat Completions image/PDF parts, Anthropic image/PDF blocks and Cohere image parts. Text-like files use strict UTF-8 decoding. Unsupported provider/format combinations return an invalid-request failure instead of silently omitting a file. Exact capabilities still depend on the selected model.
